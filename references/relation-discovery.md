# Evidence Viability 与关系发现

## 1. 先判断数据是否能回答决策问题

将可用性分为三级：

- `viable`：核心观察单位、结果、比较/时间维度和必需口径存在，可按原问题执行。
- `conditional`：只能回答原问题的一部分，必须降级问题或限定范围。
- `fatal`：核心结果变量无变异、必需比较维度为单值、观察单位与决策对象不同且无法连接、核心字段未采集，或采样机制使原比较完全失效。

`fatal` 时默认不进入编码、分组建模、稳健性、判断合成或报告工程。向用户展示影响、补数要求和可选的独立描述任务，然后等待决定。

## 2. 建立 Relation Map

先映射数据角色，不先选图：

| 角色 | 需回答 |
|---|---|
| observation | 一行是谁/什么，是否重复测量 |
| outcome | 要解释、比较或预测的结果，是否有变异 |
| group/exposure | 分组、处理、渠道、人群或内容特征 |
| time | 事件时间、观察窗口、抓取时间和频率 |
| hierarchy | 用户—笔记—账号—品牌等嵌套层级 |
| link | 多表、节点或阶段之间的连接键与粒度 |
| control | 构成、基线、暴露量或其他混杂因素 |
| uncertainty | 抽样、测量、标注、匹配、截断和小样本不确定性 |

然后生成候选关系：

- 比较：组间差异、基准偏离、排名变化。
- 分布：中心、离散、长尾、零膨胀、异常值。
- 联合结构：两个或多个分类维度的构成与交互。
- 关联：连续变量关系、非线性、分层关联。
- 时序：趋势、季节、断点、滞后、多组路径。
- 流向/转化：阶段、去向、队列、cohort。
- 网络：共现、重叠、来源—去向、多表桥接。
- 分解：总变化由规模、构成、效率或分组贡献如何构成。

## 3. 候选分析视图

每个候选视图必须记录：

- 它要回答的决策子问题；
- 需要的观察单位、变量、口径和运算；
- 可证伪的期待关系或比较基准；
- 数据是否可计算，证据强度与主要误读；
- `keep / appendix / reject` 和理由。

按“决策相关性×证据强度×可计算性”排序。不要为了显得全面计算所有交叉；但不得只做单变量榜单后声称已经发现关系。

## 4. 匹配与跨表关系的特别门槛

- 匹配规则从严格到宽松时，若核心判断发生翻转，不得选一个口径当主结论；应报告为“定义敏感，现有数据不能裁决”。
- “相关记录存在”不等于“意图已被回应”。标签、包含字符串、平台归因和内容语义是不同证据层。
- 两个指标只有在观察单位、时间窗口、去重规则和分母兼容时才能相除。
- 排名差异是候选信号，除非定义了识别机制，不得自动命名为效率、承接、竞争力或需求缺口。
